# 라이브 XY 추적 v1

`02_실험/code/live_xy.py` — 라이브 OAK 스트림(또는 녹화 영상 재생)에서 클릭으로 캘리브레이션하고
영점 대비 카메라 XY 이동을 실시간 오버레이하는 GUI 도구.

## 전제

**피사체는 움직이지 않는다.** 화면에서 관측되는 모든 KLT 이동은 카메라 자신의 이동으로 취급한다.
따라서 추적 영역의 기본값은 화면 전체이며, ROI 지정은 반사광·저텍스처 영역을 뺄 때만 쓰는 선택 기능이다.
`_STATUS.md`가 미검증으로 남긴 "피사체 움직임과 카메라 이동의 분리" 문제는 이 도구의 범위 밖이다.

## 실행

```
cd 02_실험/code
python live_xy.py                                              # OAK 라이브, 모노 글로벌셔터(CAM_B)
python live_xy.py --oak-cam color                               # IMX378 컬러 1920x1080 (롤링셔터)
python live_xy.py --source ../KakaoTalk_20260901_144821449.mp4  # 녹화 재생(회귀 검증용)
python live_xy.py --calib ../config/live_calib.json --log --record
```

## 사용 순서

1. 체커보드(`02_실험/10mm.pdf`)가 화면에 온전히 보이게 두고 `c` — mm/px 자동 산출
2. `a` → 테이블 장축(+X) 방향으로 두 점 클릭 — 부호 방향을 명시적으로 기록한다
3. (선택) `r` → 추적에서 뺄 영역이 있으면 ROI 폴리곤을 그린다. 기본은 화면 전체
4. `0` 또는 Space — 현재 위치를 영점으로 설정
5. `g`(CSV 로깅), `v`(오버레이 녹화) 로 기록 시작
6. `s` 로 캘리브레이션을 저장해두면 다음 세션에 `--calib`로 재사용 가능

## 키 바인딩

| 키 | 동작 |
|---|---|
| `c` | 체커보드 캘리브레이션 |
| `a` | 축(+X) 지정 모드 (좌클릭 2점) |
| `r` | ROI 폴리곤 그리기 (좌클릭 추가 / 우클릭 취소 / Enter 확정) |
| `0` / `Space` | 영점 재설정 |
| `f` | 특징점 강제 재검출 |
| `g` | CSV 로깅 시작/정지 |
| `v` | 오버레이 영상 녹화 시작/정지 |
| `s` | 캘리브레이션 JSON 저장 (`02_실험/config/live_calib.json`) |
| `l` | 캘리브레이션 JSON 불러오기 |
| `h` | 도움말 토글 |
| `ESC` | 현재 모드 취소 (유휴 상태면 종료) |
| `q` | 종료 |

## 좌표 규약

- world 좌표계 = 캘리브레이션 시점의 체커보드 격자, 단위 1칸 = 10 mm
- 카메라 이동: `pos_mm -= (A @ J0 @ duv) * SQUARE_MM` — `estimate_xy.py`의 fixed 스케일 정책과 동일
- `A` = 축 지정(키 `a`)으로 정한 +X(테이블 장축) 방향 치환행렬. 지정 전에는 격자축을 그대로 쓴다
- 영점(키 `0`)은 `pos_mm`을 0으로 리셋할 뿐, 별도 누적기를 두지 않는다
- 궤적 패널은 **+Y를 위로** 그린다 (`compose_xy_v1_dashboard.py`와 동일 규약).
  `report.py`는 이와 반대이므로 비교 시 주의

## 검증 결과 (이번 구현 시 수행)

- `common.py` 리팩터링 후 `python estimate_xy.py --region PRINT --scale fixed` 재현 결과가
  기존 CSV와 최대 0.0006 mm 차이(부동소수점 잡음 수준)로 일치 — 알고리즘 무변경 확인
- `live_xy.py`의 추정 루프를 기존 영상(`KakaoTalk_20260901_144821449.mp4`)에 대해 LEFT 체커보드로
  캘리브레이션 후 화면 전체 추적으로 헤드리스 실행 → mm/px=0.19376 (기존 기록값 0.1936과 일치),
  최종 오차 9.7 mm / 1.25% (기존 LEFT 대조실험 1.05%와 같은 수준) — 파이프라인 정상 동작 확인
- 실제 OAK-D-PRO-POE(192.168.0.9, CAM_B 모노 1280x800)에서 스트림 수신·정상 종료·즉시 재연결 확인
- 캘리브레이션 JSON 저장/불러오기 왕복, 해상도 불일치 거부, 축 지정 로직 단위 테스트 통과

## 확인된 위험 (설계 단계 기록, `.claude/plans/unified-frolicking-teapot.md` 참고)

1. **FOV와 보드 크기의 충돌** — 목업 0.19 mm/px는 근접 촬영값이다. 실제 테이블(1960 mm)을
   담으면 10 mm 한 칸이 너무 작아져 체커보드 검출이 불안정해진다. 실제 촬영 거리에서
   한 칸 픽셀크기를 `c` 캘리브레이션 시 확인할 것 (15 px 미만이면 경고가 뜬다)
2. **체커보드 검출에 CLAHE를 쓰면 안 된다** — 국소 대비를 과증폭해 서브픽셀 코너가 흐트러진다
   (이번 구현 중 실측: CLAHE 적용 시 RMS 16.7 px, 미적용 시 0.30 px). `live_xy.py`는 캘리브레이션에는
   항상 원본 명암을, KLT 추적에는 (옵션으로) CLAHE를 따로 쓴다
3. **글로벌 셔터(모노 CAM_B/C)가 기본값** — 롤링 셔터인 컬러(CAM_A)는 이동 중 상이 기울어진다
4. **개루프 누적 드리프트** — 무한 라이브 세션은 시간에 따라 드리프트가 커진다. 영점 리셋으로만
   완화한다. 근본 해결(체커보드 절대 앵커, 매 프레임 재적합)은 다음 단계 과제
5. **OAK 강제 종료 시 장치가 ~30초 잠긴다** — 반드시 `q`/`ESC`로 정상 종료할 것
